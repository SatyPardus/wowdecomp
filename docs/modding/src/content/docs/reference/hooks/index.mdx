ModCore declares 63 hooks, plus two that fire but are not in the typings. Register any of them with `ModCore.On(name, fn, priority)`. How return values work is explained in [Hooks and return values](/guides/hooks/).

## Reading the tables

- **Returns** `boolean?` means *consume*; `T?` means *override*; `void` means *notification*.
- **Status** `Fires` means the engine calls the hook in these commits. `Not wired` means a dispatcher exists but no engine code calls it, so listeners never run.

## Hooks fired but not in the typings

| Hook | Arguments | Fired when |
| --- | --- | --- |
| `OnSpellPacket` | `opcode: number, msg: lightuserdata` | A spell-related server message is handled in `Spell_C.cpp` |
| `OnModMounted` | `modId: string, context: table` | After `ModCore.MountMod` finishes a mod |

<Aside type="note">
Because the same dispatcher handles every name, listeners for hooks the engine never calls are harmless. They simply never run.
</Aside>
